## 0. 一句话定义

**一个把订阅账单关进保险箱的 iPhone App**：文件放在你自己的文件夹里（iCloud Drive、本机、外置），只有你的密钥或你的脸能打开它；打开后是一套正常、好用、好看的订阅台账。

## 1. 产品与设计目标

### 1.1 三条不可妥协的原则

1. **本地优先到极致**：不申请网络权限、不集成任何分析/崩溃 SDK、不做账号体系。App 里没有任何代码路径会向外发数据 —— 这是一个可以用「飞行模式」验证的隐私承诺。
2. **锁得住**：数据文件被拷走 = 一堆密文。服务端泄露、网盘被扫、手机被翻相册，都不构成泄露路径。
3. **台账要能「三分钟管完一个月」**：订阅管理的真实痛点是录入麻烦。用模板 + 智能周期 + 快捷调整把单条录入压到 4 次点击内。

### 1.2 可量化的体验预算（验收线）

| 指标 | 目标 |
|---|---|
| 冷启动 → 解锁界面出现 | ≤ 0.8s（不含 KDF） |
| Face ID 解锁（含 KDF 派生 + 解密） | ≤ 1.2s（A15 及以上） |
| 密码解锁 | ≤ 2.0s（Argon2id 参数见 §5） |
| 模板新增一条订阅 | ≤ 4 次点击 + 1 次金额确认 |
| 编辑后落盘延迟 | 600ms 防抖，切后台立即落盘；**任何时刻强杀不丢已提交的编辑** |
| 列表滚动 | 120Hz ProMotion 满帧；1000 条订阅不卡顿 |
| 数据文件体积 | 500 条订阅 ≈ 60–90 KB（JSON + GCM 后） |

### 1.3 范围

- **MVP 必须**：文件夹选择与授权持久化、密码 + 生物识别解锁、订阅 CRUD、周期归一化、模板库、续订本地通知、概览/统计、设置（改密、换文件夹、导出）、液态玻璃视觉。
- **v1.1 建议**：价格变更历史曲线、家庭分摊、CSV 导入、iPad 分栏、多币种汇率（手动维护）、Widget / Live Activity。
- **明确不做**：银行账单自动抓取、任何联网同步、账号登录。

## 2. 技术选型与关键取舍

| 决策点 | 选择 | 理由 |
|---|---|---|
| UI | SwiftUI（少量 UIKit 桥接） | 只有 SwiftUI 才能原生吃到 `.glassEffect` 等 iOS 26 材质 API；UIKit 桥接仅用于文件夹选择器与 `UIVisualEffectView` 降级兜底 |
| 持久化 | **不用** SwiftData / Core Data / 自建 SQLite | 需求是「用户文件夹里的单个加密文件」。SwiftData 的存储位置与加密策略不可控（其底层 SQLite 无法整库自定义加密），且无法原子地做「整个文档加密后落到用户选定目录」。采用**内存仓库 + 加密快照**模型，规模（数千条）完全够用 |
| 加密 | CryptoKit（AES-256-GCM / HKDF / P256）+ libsodium（Argon2id） | 系统框架优先；Argon2id 是抗 GPU 爆破的口令 KDF，CryptoKit 未提供，用 libsodium 补齐（也可退化为 PBKDF2-SHA256 600k 轮，见 §5.3） |
| 生物识别 | Secure Enclave P-256 密钥 + ECDH 派生包裹密钥 | 私钥不可导出、绑定当前生物特征集合，比「把密钥明文存 Keychain」高一个安全等级 |
| 并发 | Swift 6 严格并发；文件 IO 与解密在 `actor` 内，UI 状态 `@MainActor` | 避免加解密阻塞主线程，同时保证同一时刻只有一次落盘 |
| 第三方依赖 | 仅 `swift-sodium`（可用 CryptoKit + CommonCrypto 完全替代） | 明文依赖越少，审计成本越低 |

## 4. 架构设计

### 4.1 分层与数据流

```
┌──────────────────────────────────────────────────────┐
│  View (SwiftUI, @MainActor)                          │
│  ↑ @Observable 状态  ↓ Intent（方法调用）              │
├──────────────────────────────────────────────────────┤
│  FeatureModel (@Observable, @MainActor)              │
│  - 视图状态机、表单校验、派生视图数据                    │
├──────────────────────────────────────────────────────┤
│  VaultRepository (protocol, Sendable)                │
├──────────────────────────────────────────────────────┤
│  VaultStore (actor)  ← 唯一可触碰密文与密钥的地方        │
│  - 串行化写入 / 防抖 / 版本号 / 冲突检测 / 锁定          │
├──────────────────────────────────────────────────────┤
│  VaultFileCodec + VaultKeyring (WSCrypto)            │
│  FolderAccess (security-scoped bookmark + 文件协调)    │
└──────────────────────────────────────────────────────┘
```

**单向数据流**：View 调用 `FeatureModel` 的方法 → `FeatureModel` 构造不可变 `Mutation` 交给 `VaultStore` → `VaultStore` 应用到内存快照、落盘、并通过 `AsyncStream<VaultEvent>` 广播 → `FeatureModel` 订阅事件刷新 `@Observable` 属性。

**为什么快照是不可变值类型**：`VaultSnapshot` 是 `struct`（`Sendable`），跨 actor 传递零成本（COW），避免共享可变状态的数据竞争；落盘时编码的是「某一时刻的完整一致视图」。

### 4.2 `VaultStore` 契约（核心代码骨架）

```swift
public actor VaultStore {
    public enum State: Sendable {
        case locked, unlocking, unlocked(VaultHandle), failed(VaultError)
    }

    private var handle: VaultHandle?          // 含内存快照 + 密钥句柄 + 文件版本
    private var saveTask: Task<Void, Never>?  // 防抖落盘
    private var eventContinuations: [UUID: AsyncStream<VaultEvent>.Continuation] = [:]

    /// 解锁：一次完成 KDF → 解包主密钥 → 校验头 MAC → 解密负载
    public func unlock(using credential: UnlockCredential) async throws -> VaultSnapshot

    /// 提交变更：立即应用到内存快照，600ms 防抖后落盘
    public func apply(_ mutations: [VaultMutation]) async throws

    /// 强制落盘（切后台、手动保存、退出前）
    public func flush() async throws

    /// 锁定：取消待写入、清零密钥、丢弃明文快照
    public func lock()

    public func events() -> AsyncStream<VaultEvent>
}
```

`VaultHandle` 只在 `VaultStore` 内部可见，UI 永远只拿到 `VaultSnapshot` 的只读副本。

### 4.3 自动保存与一致性

| 触发 | 行为 |
|---|---|
| 任意 mutation | 标记 dirty，启动/重启 600ms 防抖任务 |
| 防抖到期 | 编码 → 加密 → 写临时文件 → 校验 → 原子替换 → 保留上一版为 `.bak` |
| `scenePhase == .background` / `willResignActive` | `flush()` 同步等待（受 `beginBackgroundTask` 保护，最多 ~5s） |
| 落盘失败（磁盘满、书签失效、iCloud 冲突） | 进入 `degraded` 态：顶部常驻警示条 + 重试队列 + 手机内**应急副本**（Application Support 下的同样加密文件），恢复后自动对账 |
| App 强杀 | 因每次 mutation 后 600ms 内必落盘，最坏丢失最近 600ms 的输入；编辑器内文本在 `onChange` 即写回内存快照，故不会丢 |

### 4.4 错误模型

统一 `VaultError`（`LocalizedError`，每个 case 配一句人话文案 + 一个可执行动作）：

| case | 用户可见文案 | 动作 |
|---|---|---|
| `.folderPermissionLost` | 文件夹访问权限已失效（可能被移动或删除） | 「重新选择文件夹」 |
| `.wrongPassphrase(attemptsLeft:)` | 密码不正确，还可尝试 N 次 | 抖动 + 退避 |
| `.biometryUnavailable` | 此设备暂不可用 Face ID | 切换到密码 |
| `.fileTampered` | 数据文件校验失败，可能已被外部修改 | 「从备份恢复」 |
| `.revisionRollback(detected:)` | 文件版本比本机记录更旧 | 「以文件为准 / 以本机为准」 |
| `.diskFull` | 存储空间不足，本次修改已缓存待重试 | 自动重试 |

## 5. 加密与安全存储机制

### 5.1 威胁模型

| 攻击者能力 | 是否防御 | 手段 |
|---|---|---|
| 拿到数据文件（网盘泄露、备份被拷） | ✅ | 全量 AES-256-GCM，密钥不在文件内 |
| 拿到设备但不知道密码、无法通过 Face ID | ✅ | 主密钥被双重包裹；SE 私钥不可导出 |
| 拿到设备且强制你刷脸 | ⚠️ 部分 | 提供「紧急锁定」（快捷指令/锁屏小组件），可一键清除内存密钥并要求密码；系统级不可完全防御，需在文档中诚实说明 |
| 内存 dump / 调试器附加 | ⚠️ 部分 | 密钥置于 `SecureBytes`（`mlock` + 退出即 `memset_s`）；Release 关闭 `-Onone`；不写日志 |
| 篡改文件、回滚到旧版本 | ✅ | 头部 HMAC + `revision` 单调计数 + 本机 Keychain 记录最高版本 |
| 侧信道计时攻击 KDF | ✅ | 恒定时间比较（`CryptoKit` 自带）；失败路径也执行等量 KDF |
| 越狱设备上的恶意注入 | ❌ 超出范围 | 不做越狱检测（徒增误报），但在隐私说明中告知边界 |

### 5.2 密钥层级（本方案的心脏）

只有一把真正的密钥，三条各自独立的「开锁路径」都能拿到它：

```
                    随机生成 256-bit
                    ┌──────────────────┐
                    │   Master Key MK  │  ← 只存在于内存中，永不落盘
                    └────────┬─────────┘
        包裹（加密）三次，形成三个独立的钥匙孔
     ┌───────────────┬───────┴────────┬──────────────────┐
     ▼               ▼                ▼                  ▼
 口令路径         生物识别路径       恢复密钥路径        （可选）仅本机
 Argon2id        Secure Enclave     Recovery Key
 → KEK_pass      P-256 私钥 ECDH     → KEK_recovery
                 → KEK_bio
     │               │                │
     └──── AES-GCM 包裹 MK，三段密文一起写进文件头 ────┘
```

- **MK（主密钥）**：32 字节随机，`SecRandomCopyBytes` 生成。它直接用于 AES-256-GCM 加密整个数据负载。改密码、换 Face ID 都**只重新包裹 MK，不重新加密数据** —— 这是信封加密最大的工程收益。
- **KEK_pass**：`Argon2id(passphrase, salt=16B, m=64MiB, t=3, p=2)` → 32 字节。每次建库生成独立 salt 并写入文件头。
- **KEK_bio**：Secure Enclave 生成 P-256 密钥对（`kSecAttrTokenIDSecureEnclave` + `.biometryCurrentSet` + `.privateKeyUsage`）。建库时用一个**临时 P-256 公钥**与之 ECDH，得到共享密钥 → `HKDF-SHA256(sharedSecret, salt: 32B, info: "ws.bio.kek.v1")` → 32 字节。临时私钥用后即弃。解锁时反向：临时密钥对 → 与 SE 公钥 ECDH（此时系统自动弹 Face ID）→ 同一 KEK。
  - **为什么用 SE 而不是「Keychain 里存一把随机 key」**：SE 私钥物理不可导出，即便攻击者拿到 Keychain 数据库也无法在别的设备上还原；且 `.biometryCurrentSet` 让「新增一张脸/一枚指纹」自动作废该密钥 —— 安全语义正确，且因为密码路径永远存在，不会锁死用户。
- **KEK_recovery**：24 组 Base32 恢复码（120 bit 熵）→ `Argon2id`（参数略低，m=32MiB/t=3）→ 32 字节。
- **口令派生密钥的派生**：`MK` 不直接用于加密负载，而是 `HKDF(MK, info:"ws.payload.v1")` 得到 `PayloadKey`，`HKDF(MK, info:"ws.header.mac.v1")` 得到 `HeaderMACKey`。用途分离，避免同一密钥跨用途复用。

### 5.3 数据文件格式（`.wsvault`）

单文件、自描述、头部明文但**被认证**。这样任何未来版本的 App 都能读到 KDF 参数并解密。

```
┌───────────────────── Header（明文，被 HeaderMAC 覆盖） ─────────────────────┐
│ magic            "WSVL"                    4B                             │
│ formatVersion    UInt16                    2B   (当前 1)                  │
│ flags            UInt16                    2B   bit0 有生物识别 bit1 有恢复码│
│ kdfID            UInt8                     1B   1=Argon2id 2=PBKDF2       │
│ kdfParams        mCost u32, tCost u8, p u8 6B                             │
│ saltPass         16B                                                      │
│ saltBio          16B                                                      │
│ wrapPass         nonce12 + ct32 + tag16    60B                            │
│ wrapBio          ephPub65 + nonce12 + ct32 + tag16 = 125B                 │
│ wrapRecovery     nonce12 + ct32 + tag16    60B                            │
│ revision         UInt64                    8B   单调递增，用于冲突/回滚检测 │
│ writerDeviceID   UUID                      16B                            │
│ payloadNonce     12B                                                      │
│ headerMAC        32B   = HMAC-SHA256(HeaderMACKey, 前面所有字节)           │
└───────────────────────────────────────────────────────────────────────────┘
┌──────────────── Payload（密文） ────────────────┐
│ AES-256-GCM(PayloadKey, nonce=payloadNonce,    │
│             aad = Header 全部字节,             │
│             plaintext = JSON(VaultSnapshot))   │
└────────────────────────────────────────────────┘
```

设计要点：

1. **AAD 绑定头部**：任何对 `revision`、KDF 参数、包裹段的篡改都会让 GCM 解密失败。
2. **HeaderMAC 需要 MK**：只有成功解包 MK 后才能验证，因此它能拦住「降级攻击」（把 kdf 参数改成弱参数）与「版本回滚」。
3. **明文头不泄露内容**：只暴露「这是一个 W Subscription 保险箱、用了什么 KDF」，这是解密所必需的公开参数。
4. **负载用 JSON 而非二进制**：负载本身已被加密，用 JSON 换来的是可调试、可迁移、向后兼容（新增字段 = 忽略未知键 + 默认值）。

### 5.4 三条解锁路径

```swift
public enum UnlockCredential: Sendable {
    case passphrase(String)
    case biometry(context: LAContext)
    case recoveryKey(String)
}

func unlock(using credential: UnlockCredential) async throws -> VaultSnapshot {
    let file = try folder.readVaultFile()            // 1. 读文件（协调 + 作用域）
    let header = try VaultFileCodec.parseHeader(file) // 2. 解析明文头
    let mk = try await keyring.unwrapMasterKey(header, using: credential) // 3. 解包 MK
    try header.verifyMAC(with: mk)                    // 4. 防篡改 / 防回滚
    let snapshot = try VaultFileCodec.decryptPayload(file, header, mk)    // 5. 解密
    return try SchemaMigrator.migrateIfNeeded(snapshot)                   // 6. 迁移
}
```

**失败语义**：第 3 步失败 = 密码错误（走退避计数）；第 4 步失败 = 文件被篡改/回滚（**不增加**密码尝试计数，避免把攻击者行为算到用户头上）；第 5 步失败 = 文件损坏（引导用 `.bak` 或应急副本）。

### 5.5 生物识别的正确接法

```swift
// 建库时：让 SE 保护一把「解包用」私钥
let access = SecAccessControlCreateWithFlags(
    nil,
    kSecAttrAccessibleWhenPasscodeSetThisDeviceOnly,
    [.privateKeyUsage, .biometryCurrentSet],
    &error
)!
let attrs: [String: Any] = [
    kSecAttrKeyType as String: kSecAttrKeyTypeECSECPrimeRandom,
    kSecAttrKeySizeInBits as String: 256,
    kSecAttrTokenID as String: kSecAttrTokenIDSecureEnclave,
    kSecPrivateKeyAttrs as String: [
        kSecAttrIsPermanent as String: true,
        kSecAttrApplicationTag as String: Data("app.wsubscription.bio".utf8),
        kSecAttrAccessControl as String: access
    ]
]
let seKey = SecKeyCreateRandomKey(attrs as CFDictionary, &error)!
let sePub  = SecKeyCopyPublicKey(seKey)!
```

- **触发 Face ID 的方式**：不手动调 `LAContext.evaluatePolicy`，而是让 `SecKeyCopyKeyExchangeResult` 自己弹窗（`kSecUseAuthenticationContext` 传入自定义 `LAContext` 以设置提示语「解锁你的订阅保险箱」）。少一次系统弹窗、少一次竞态。
- **能力检测**：`LAContext().canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error:)` 为 false（模拟器、无 Face ID 的机型、未设锁屏密码）时，整条生物识别路径在 UI 上不出现，而不是出现后失败。
- **失效处理**：`.biometryCurrentSet` 在用户新增/删除生物特征后会返回 `LAError.biometryNotAvailable` 类错误 → 自动回落到密码解锁，并在设置页提示「请重新启用 Face ID」（重新包裹 MK 即可，数据不动）。

### 5.6 内存与生命周期

| 资源 | 存放位置 | 清除时机 |
|---|---|---|
| MK / PayloadKey / KEK | `SecureBytes`（`mlock` + `memset_s` 析构） | 锁定、切后台超时、`deinit` |
| 明文 `VaultSnapshot` | 仅 `VaultStore` 内 | 锁定即置 nil，UI 侧 `@Observable` 同步清空 |
| 密码输入 | `UITextField`（`isSecureTextEntry`），只转 `Data`，不转 `String` 常量池 | 提交后立刻清零 |
| SE 私钥 | Secure Enclave | 不可导出，天然安全 |
| 恢复码 | 仅展示一次，不落盘 | 用户确认已抄写即丢弃 |

- **自动锁定策略**：`立即 / 30 秒 / 1 分钟 / 5 分钟`（默认 30 秒，仅后台计时；前台不锁）。手动锁屏按钮常驻设置页顶部与「快捷指令」。
- **截屏保护**：解锁界面与恢复码页面加 `UITextField.isSecureTextEntry` 同款遮罩（监听 `UIScreen.capturedDidChangeNotification` 覆盖黑层），避免恢复码进入用户相册。
- **键盘**：密码框设 `textContentType = .password` 会触发系统强密码建议，反而干扰 —— 用 `.oneTimeCode` 之外的空配置 + `autocorrectionType = .no`，并禁用「自动填充」。

### 5.7 防爆破与恢复

- 失败计数存 Keychain（`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`），**不存文件**（文件可被替换绕过）。
- 退避：1→2→4→8→…→300s 封顶；第 5 次起界面上显示剩余等待秒数。**不提供「忘记密码 → 邮箱重置」**（没有服务端），只提供恢复码。
- 第 10 次可配置「清空本机数据」（默认关闭，开启需二次确认）。清空只删访问权限与内存态，**不删用户文件夹里的文件** —— 那是用户的数据，删不删由用户自己决定。
- **恢复码是唯一的救命绳**：建库流程强制展示 + 强制「我已抄写」勾选 + 可导出为 PDF/打印。设置页常驻「查看/重新生成恢复码」（重新生成 = 用新恢复码重新包裹 MK，旧码立即失效）。

### 5.8 密钥轮换

| 操作 | 计算量 | 实现 |
|---|---|---|
| 修改密码 | 2 次 Argon2id + 2 次 GCM | 解包 MK → 用新 KEK 重新包裹 → 覆盖 `wrapPass` + 新 salt → 重算 HeaderMAC → 落盘 |
| 换指纹/面容 | 1 次 ECDH + GCM | 生成新 SE 密钥 → 重新包裹 MK → 覆盖 `wrapBio` |
| 重新生成恢复码 | 1 次 Argon2id | 同上 |
| 更换文件夹 | 0 次 KDF | 解密 → 写到新目录同名文件 → 更新书签 → 删除旧文件（二次确认） |
| 全量重新加密（换算法/升级格式） | 1 次解密 + 1 次加密 | 新 formatVersion，迁移链 |

### 6.2 金额：绝不用 `Double`

```swift
public struct Money: Codable, Hashable, Sendable {
    public var minorUnits: Int64      // 最小货币单位（分）；JPY 为「元」，KWD 为「千分之一」
    public var currencyCode: String   // ISO 4217

    /// 该币种的小数位数（JPY=0、CNY=2、KWD=3），由 Locale 推导并缓存
    public var fractionDigits: Int
    public var decimal: Decimal { Decimal(minorUnits) / pow(10, fractionDigits) }
    public func formatted(style: FormatStyle = .standard) -> String
}
```

- 存储 `minorUnits` 而非 `Decimal` 字符串：排序、求和、去重全部是整数运算，零精度损失。
- 展示走 `Decimal.FormatStyle.Currency`，跟随系统区域。
- 多币种不做实时汇率；`AppSettings.manualRates: [String: Decimal]` 由用户维护，默认 1:1 只做「分币种汇总」。

### 6.3 计费周期与归一化（最容易出错的地方）

```swift
public enum BillingCycle: Codable, Hashable, Sendable {
    case weekly, biweekly, monthly, quarterly, semiAnnually, annually
    case customDays(Int)     // 如 45 天
    case customMonths(Int)   // 如 每 3 个月
    case oneTime             // 一次性买断，不计入月度支出

    /// 折算为「每月等值」，用于概览与统计；输出保留 4 位小数，展示时四舍五入到分
    public func monthlyEquivalent(of amount: Decimal) -> Decimal
}
```

归一化规则（写进单元测试，逐条断言）：

| 周期 | 月均 = |
|---|---|
| 每周 | `× 52 / 12` |
| 双周 | `× 26 / 12` |
| 每月 | `× 1` |
| 每季 | `÷ 3` |
| 半年 | `÷ 6` |
| 每年 | `÷ 12` |
| 自定义 N 天 | `× (365.25 / N) / 12` |
| 自定义 N 月 | `÷ N` |
| 一次性 | 不计入（单独展示为「已买断」） |

**下次扣款日**：以 `anchorDate`（首次扣款日）为锚点向前推进整周期，**月末夹取**规则 —— 1 月 31 日的月付，2 月落在 28/29 日，3 月回到 31 日（不做「一路下跌」的漂移）。闰年、跨年、时区（统一用 `Calendar(identifier: .gregorian)` + 用户当前时区，日期只存 `Date` 的日粒度语义 + 时区快照）。

### 6.6 迁移

- `schemaVersion` 单调递增，`SchemaMigrator` 持有 `[Int: (inout RawSnapshot) throws -> Void]` 迁移链，逐级升级，任何未知的未来版本直接拒绝打开并提示「请升级 App」（防止新版本写入的字段被旧版本静默丢弃）。
- 迁移在**解密后、进入内存仓库前**执行；迁移完成后立即落盘一次，避免每次启动重复迁移。
- 迁移失败 = 致命错误，**不改原文件**，只提示「文件格式异常」并提供 `.bak` 恢复入口。

### 6.7 冲突合并（多设备共用一个网盘文件夹时）

不追求完整 CRDT，用 **LWW-Element-Set + 墓碑**，够用且可控：

- 每条记录带 `updatedAt` + `deviceID`；合并时 `updatedAt` 大者胜，相同则 `deviceID` 字典序大者胜（确定性）。
- 删除写墓碑（`id + deletedAt + deviceID`），保留 90 天。
- 检测时机：落盘前比对文件的 `revision` 与本机记录；不一致 → 拉取文件、解密、合并、双方各写一次。
- 合并失败（文件被另一台设备改了密码 → MK 不同）→ 明确提示「此文件夹中的保险箱已被另一台设备重新设置密码」，不静默覆盖。

## 7. 文件夹访问与文件 IO

### 7.1 书签：iOS 上最容易被低估的坑

```swift
// 选择：UIDocumentPickerViewController(forOpeningContentTypes: [.folder], asCopy: false)
func persist(_ url: URL) throws -> Data {
    guard url.startAccessingSecurityScopedResource() else { throw VaultError.folderPermissionLost }
    defer { url.stopAccessingSecurityScopedResource() }
    return try url.bookmarkData(options: [], includingResourceValuesForKeys: nil, relativeTo: nil)
}
```

工程约束与对策：

| 约束 | 对策 |
|---|---|
| 每次访问都要 `start/stopAccessingSecurityScopedResource`，且同时打开的作用域数量有限 | `FolderAccess` 内部串行化，一次 IO 一次作用域，`defer` 保证关闭 |
| 书签可能 stale（文件提供者容器变化、iCloud 重装、文件夹被移动） | 解析后立即 `startAccessing` 探测；失败 → `.folderPermissionLost`，进入「重新授权」流程（见 §9.6） |
| iOS 上无法静默重新授权 | 记住**文件名 + 相对结构**，重新选择时自动定位到同名 `.wsvault`，用户只需点两下 |
| iCloud Drive 可能尚未下载 | 读之前 `URLResourceValues.ubiquitousItemDownloadingStatus`，必要时 `startDownloadingUbiquitousItem` 并显示进度 |
| 其他进程（Files、快捷指令）可能同时写 | 全部写入包在 `NSFileCoordinator` 的 `coordinate(writingItemAt:.forReplacing)` 内 |
| 外置 U 盘/USB-C 拔出 | IO 抛错 → 降级到应急副本，保留待重试 |

### 7.2 原子写

```
1. 编码+加密得到 Data（内存，~几十 KB）
2. 写入同目录 vault.tmp.<uuid>（同卷，保证 rename 原子）
3. 读取 tmp 并校验 magic + headerMAC 长度（写入即验证）
4. FileManager.replaceItemAt(vaultURL, withItemAt: tmp, backupItemName: "vault.bak")
5. 更新本机 revision 记录（Keychain）
```

- 失败任一步：删除 tmp，保留原文件，返回可重试错误。
- 首次创建（无原文件）：直接 `Data.write(to:options:.atomic)`。
- `.bak` 只保留一代（用户文件夹要保持干净），恢复入口在设置页。

### 7.3 文件命名与目录洁净

用户看到的是：

```
我的订阅/
└── WSubscription.vault     ← 单文件，~60KB，无扩展名图标干扰
```

不建子目录、不写 `.DS_Store`、不散落日志。文件名固定、不含日期；用户若要手动备份，复制这一个文件即可 —— 这本身就是最好的备份体验。

## 9. 关键交互流程

### 9.1 首次配置（目标：90 秒内完成，不吓人）

```
① 欢迎页（3 屏可滑动，第 3 屏一句"数据只在你选的文件夹里"）
   ↓ 开始
② 选择文件夹   ← 系统文件选择器（.folder），页面明确说"建议选 iCloud Drive 下的新建文件夹"
   ↓ 选中
③ 设置密码     ← 强度提示（≥8 位，含大小写/数字/符号任一加分），实时显示"破解所需时间"估算
   ↓ 下一步
④ 恢复码       ← 24 组，逐字可读，一键复制/存到「文件」，强制勾选"我已妥善保存"
   ↓ 下一步
⑤ 启用 Face ID ← 可选，一句话解释"Face ID 只是另一把钥匙，密码永远有效"
   ↓ 完成
⑥ 选几个你正在订阅的 ← 模板多选（跳过也可），批量生成初始数据
   ↓
⑦ 概览页，玻璃卡片浮现动画
```

**边界**：任一步骤退出 → 草稿存 Application Support（加密，密钥临时存 Keychain），下次启动从中断处继续；`.wsvault` 尚未落盘则不写入用户文件夹（不留垃圾）。

### 9.2 解锁（每次冷启动 / 超时回前台）

```
App 启动 → 读书签 → 探测文件存在
   ├─ 文件不存在 → "找不到数据文件" 页：重新选择 / 新建
   └─ 存在 → 锁定页
        ├─ 已启用 Face ID → 自动触发（0.6s 延迟，避免和启动动画打架）
        │     ├─ 成功 → 解包 MK → 校验 → 解密 → 进入（无转场，直接 fade in）
        │     └─ 失败/取消 → 保持在密码输入，按钮变为"使用密码"
        └─ 输入密码 → 提交 → 键盘收起 → 进度环（KDF 期间，~0.6s）
              ├─ 成功 → 进入
              └─ 失败 → 抖动 + 剩余次数 + 退避倒计时
```

**细节**：KDF 在 `Task.detached(priority: .userInitiated)` 上跑，主线程只显示进度；密码错误时不 reset 输入框，而是全选方便重输。

### 9.3 添加订阅（4 次点击达成）

`+`（玻璃浮动按钮）→ 模板网格（点 1 下选中 Netflix）→ 金额键盘（输 3 位，点"完成"）→ 保存。分类/周期/下次扣款全部有智能默认值（周期默认月付、锚点默认今天、提醒默认提前 3 天）。表单底部一行「更多选项」（试用、备注、标签、提醒）折叠，不打扰主路径。

### 9.4 续订提醒

- 落盘成功 → 重算通知：每条活跃订阅 × 每个 `reminderOffset` 一个 `UNNotificationRequest`（id `sub.<uuid>.<offset>`）。
- **iOS 待处理通知上限 64 条**：超过时按「触发时间最近」保留 56 条，其余在下次启动/编辑时滚动补齐。这是必须处理的硬约束，否则用户会发现"提醒莫名不响了"。
- 通知文案：`Netflix 将于 3 天后自动续费 · ¥88.00`；点开直达该订阅详情（自定义 `UNNotificationAction` + `userInfo` 带 id）。
- 静默时段：22:00–08:00 的提醒顺延到 08:00（`UNCalendarNotificationTrigger` 直接算好，不用后台任务）。

### 9.5 修改密码

设置 → 安全 → 修改密码 → 验证旧密码（或 Face ID）→ 输新密码两次 → 重新包裹 → 落盘 → Toast「密码已更新，旧密码立即失效」。

### 9.6 文件夹权限失效 / 换设备

```
检测到 .folderPermissionLost
  → 全屏说明页（不弹 alert，重要流程给足空间）
  → "重新选择文件夹"
  → 系统选择器（记住上次路径，用户通常直接落在原目录）
  → 选中后：若目录内有同名 .wsvault → 直接接管
           若无 → 提示"未找到数据文件"，提供两个选项：
                a) 改为"打开已有文件"（选择 .wsvault）
                b) 视为首次使用，新建库（旧文件仍在原处，不会被删）
```

### 9.7 导出

| 形式 | 说明 | 风险提示 |
|---|---|---|
| 加密副本 | 复制 `.wsvault` 到用户指定位置 | 无（仍是密文） |
| CSV 明文 | 导出订阅台账表格 | **必须二次生物识别确认 + 红字提示"此文件不加密"** |

### 9.8 后台锁定

## 10. 视觉：液态玻璃（Liquid Glass）实现要点

### 10.1 设计语言

| 令牌 | 值 |
|---|---|
| 圆角 | 卡片 24 / 大容器 32 / 小控件 14（全部 `.continuous`） |
| 间距 | 4pt 网格；页面边距 20；卡片内边距 16 |
| 字体 | `SF Pro`（标题 `.rounded` 变体用于金额）；金额一律 `.monospacedDigit()` |
| 主色 | 中性玻璃 + 每个分类一个品牌色 tint；不使用大面积品牌色块 |
| 背景 | `MeshGradient` 三色缓慢流动（分类色低饱和叠加），**玻璃需要有东西可折射才好看** |
| 动效 | 基础 spring `response 0.35 / damping 0.82`；数字变化用 `.contentTransition(.numericText())`；卡片展开用 `matchedGeometryEffect` |

### 10.2 原生 API 用法（iOS 26）

```swift

    @ViewBuilder var content: Content

        content
            .padding(16)
            .glassEffect(
                tint.map { Glass.regular.tint($0.opacity(0.35)).interactive() } ?? .regular,
                in: .rect(cornerRadius: 24)
            )
    }
}
```

**其他在 iOS 26 上"自动变玻璃"的地方（不要重复造）**：

- 底部 `TabView`（`Tab` API）默认就是浮起的玻璃条，配合 `.tabBarMinimizeBehavior(.onScrollDown)` 在滚动时收起，给内容让位。
- 导航栏按钮：`ToolbarItem` + `.buttonStyle(.glass)`；用 `ToolbarSpacer(.fixed)` 做分组间距。
- 表单控件（`Toggle` / `Slider` / 分段 `Picker`）系统已换成玻璃质感，**不需要也不应该在下面再垫一层玻璃**。
- Sheet：`presentationDetents` 不变，背景自动玻璃化；需要内容与背景融合时用 `.presentationBackground(.clear)` 自绘。
- 大图/大色块延伸到栏下：`.backgroundExtensionEffect()`。
- 列表顶边滚动过渡：`.scrollEdgeEffectStyle(.soft, for: .top)`。

### 10.3 分层规则（决定"高级"还是"廉价"）

1. **玻璃是功能层，不是装饰**：只用于「悬浮于内容之上」的元素 —— 浮动按钮、底部操作条、滚动时吸顶的摘要条、模态面板。**列表行、内容卡片大面积铺玻璃 = 视觉噪音 + 掉帧。**
2. **最多两层**：玻璃叠玻璃会糊成一团灰。需要层次时用「玻璃 + 实色卡片」或「玻璃 + 阴影」。
3. **一屏最多 3 个玻璃组**，同组用 `GlassEffectContainer` 合并。
4. **必须可读**：玻璃上的文字用 `.primary/.secondary` 语义色而非硬编码灰；关键数字加重并加轻微内阴影。
5. **背景要有内容**：纯白背景上的玻璃几乎不可见 —— 所以要有 MeshGradient / 分类色光晕垫底。

### 10.4 降级与无障碍

```swift
extension View {
    func wsGlass(cornerRadius: CGFloat = 24, tint: Color? = nil) -> some View {
        modifier(WSGlassModifier(cornerRadius: cornerRadius, tint: tint))
    }
}

struct WSGlassModifier: ViewModifier {
    @Environment(\.accessibilityReduceTransparency) private var reduceTransparency
    @Environment(\.colorScheme) private var scheme

    func body(content: Content) -> some View {
        if #available(iOS 26.0, *), !reduceTransparency {
            content.glassEffect(.regular.tint(tint ?? .clear), in: .rect(cornerRadius: cornerRadius))
        } else {
            content
                .background(.regularMaterial, in: .rect(cornerRadius: cornerRadius))
                .overlay(
                    RoundedRectangle(cornerRadius: cornerRadius, style: .continuous)
                        .strokeBorder(.white.opacity(scheme == .dark ? 0.10 : 0.55), lineWidth: 0.8)
                )
                .shadow(color: .black.opacity(0.06), radius: 12, y: 4)
        }
    }
}
```

- **降低透明度**开启 → 全部换成 `regularMaterial` 或直接实色面板（用户开了这个开关通常是因为看不清）。
- **增强对比度** → 描边加深、文字去半透明。
- **减弱动态效果** → 关闭 MeshGradient 动画与形变，保留淡入淡出。
- **动态字体** → 支持到 AX5；玻璃卡片改为垂直堆叠，金额不省略小数点。
- **VoiceOver** → 卡片合并为一个 accessibility element，label 形如「Netflix，每月 88 元，3 天后续费」。

### 10.5 性能守则

| 风险 | 对策 |
|---|---|
| 玻璃层过多导致离屏渲染 | 一屏 ≤ 3 组，`GlassEffectContainer` 统一管理 |

## 15. 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| iOS security-scoped bookmark 在部分文件提供者上不稳 | 用户"打不开自己的数据" | 三级兜底：书签 → 应急副本（App 内）→ 重新选择文件；全流程可恢复，绝不静默失败 |

| 多设备共用一个网盘目录 | 数据互相覆盖 | LWW 合并 + revision 检测 + 明确提示，不做静默覆盖 |

## 16. 实施记录（v1.0 代码已落地）

本节记录实际写出来的东西与上文的差异，避免文档与代码两张皮。

| 项 | 落地情况 |
|---|---|
| 工程 | `WSubscription.xcodeproj`（objectVersion 77，文件系统同步组）+ 一个本地 SPM 包，5 个 target |
| 规模 | 29 个 Swift 文件 / 约 6100 行（含注释） |
| 测试 | 51 个单测全绿：加密往返、篡改、回滚、密钥轮换、恢复码、月末夹取、闰年、跨币种、合并确定性、模板别名检索 |
| 构建 | `xcodebuild ... -destination 'iOS Simulator'` BUILD SUCCEEDED；已在 iPhone 模拟器（iOS 26.3）安装运行并逐屏截图 |
| 液态玻璃 | iOS 26 走原生 `.glassEffect` / `.glassProminent` / `.tabBarMinimizeBehavior`；iOS 18–25 走 `regularMaterial` + 镜面描边降级；背景为分层模糊椭圆，给玻璃提供折射内容 |

实现期修正的几个设计细节（文档已同步）：

1. **P-256 公钥表示不统一**：`SecKeyCopyExternalRepresentation` 返回 65 字节（0x04 前缀），CryptoKit 的 `rawRepresentation` 是 64 字节。文件里统一存 65 字节 X9.63，读入时去掉前缀给 CryptoKit，写出时补前缀给 Security。不统一会让 Secure Enclave 整条路径静默失效。
2. **恢复码分隔符不能参与派生**：`RecoveryKey.generate()` 返回裸 24 字符，展示时才加分隔符。首版把格式化字符串拿去派生，导致恢复码 100% 解锁失败 —— 被 `testRecoveryKeyUnlocksSameMasterKey` 抓到。
3. **三段盐必须独立**：`saltPass` / `saltRecovery` / `saltBio` 分开，否则改密码会顺手废掉恢复码和生物识别。
4. **计费日集合用半开区间** `[start, end)`：`DateInterval.contains` 是闭区间，会让区间末尾多算一次扣款。
5. **悬浮按钮必须放在页面内容层**：放在 `TabView` 外层 overlay 会压在 iOS 26 的浮动标签栏上。

未完成的验证项：真机 Face ID 解锁、文件夹选择器的端到端授权、通知真实送达、iPad 分栏。

### 17.7 修：iCloud 云盘里的文件夹选不了

现象：在系统选择器里能看到 iCloud 云盘的目录，但整行是灰的，点不进去也选不了。

根因是**文档选择器的语义**，不是权限：

1. SwiftUI 的 `.fileImporter` 默认走「导入」语义 —— 把选中项目复制到 App 的 Inbox。文件夹没有「复制一份」的说法，系统于是把它标成不可选。只有在 `LSSupportsOpeningDocumentsInPlace = YES` 时它才改用「就地打开」。
2. 即使加上那个键，把 `UIDocumentPickerViewController` 塞进 SwiftUI 的 `.sheet` 也会得到一个残缺的界面：顶部没有「打开」按钮，用户只能一路往里钻，选不了当前这一层。

修法：

- `INFOPLIST_KEY_LSSupportsOpeningDocumentsInPlace = YES`（Debug/Release 都加）。
- 新增 `FolderPickerPresenter`：`UIDocumentPickerViewController(forOpeningContentTypes: [.folder], asCopy: false)`，从窗口最上层控制器直接 `present`，并静态持有 picker 与 delegate。
- `FolderAccess.withAccess` 不再把 `startAccessingSecurityScopedResource()` 返回 false 当失败。它返回 false 只表示「这个 URL 不需要作用域」，iCloud 返回的 URL 经常如此；真正的失败交给后续 IO，并把 `NSFileRead/WriteNoPermission` 翻译成 `folderPermissionLost`。
- 选完立刻 `verifyWritable()`：往目录里写一个 1 字节探针再删掉。iCloud 里别人共享的只读文件夹会在这一步被挡住，而不是等用户输完密码建库时才失败。新增错误 `notWritableFolder`。

回归测试 3 条（`TestVault` 目录下）：无作用域 URL 仍可读写、只读目录被提前拒绝、书签往返后目录仍可用。

### 17.9 修：文件夹选择器「打开」点了没反应（v1.1.2）

### 17.12 翻页不闪 + 卡片再收一点（v1.1.4）

- **闪一下的根因**：旧实现是「拖完 → 换 index → 重设 drag」，换的那一帧新旧卡片同时重建，视觉上就是一次跳变。改成**连续位置翻页器**：只有一个 `position: CGFloat`，手指移动时直接改它，卡片按 `d = 卡片序号 − position` 连续换算缩放/位移；翻走的卡向上滑出并被堆叠区裁掉，下一张连续放大到 1。全程没有「换卡」这一帧。

### 17.13 修：翻页仍然闪一下（v1.1.5）

上一版把「换 index」改成了连续 position，但闪还在。真正的原因是**视图重建**，不是动画：

1. `stackedCard` 里写了 `if entry.index == currentIndex { 卡.onTapGesture } else { 卡.allowsHitTesting(false) }`。`_ConditionalContent` 的两个分支是不同类型，`currentIndex` 在翻页中途翻转时，SwiftUI 会把整棵子树销毁重建 —— 就是那一下闪。
   → 改成无分支：`.allowsHitTesting(entry.index == index)`，只有修饰符参数变，视图不重建。
2. `zIndex` 用的是连续值 `20 - d`，每帧都在变，会触发重新排序。
   → 改成整数距离 `-abs(entry.index - index)`，只在 index 变化时改。
3. 卡片本身带了 `depth`，拖动时每帧都重新求值整个卡片 body。
   → `depth` 从卡片里拿掉，压暗层改成外层 `.overlay`，卡片在拖动期间完全不重算。
4. 叠放区单独抽成 `SubscriptionDeck`，`position` 只在这个视图里变，上面的两张支出卡不会跟着每帧重绘。

图标箭头反向：以缺口中心（-45°）为轴做一次镜像，缺口仍在右下角、尾巴仍是斜切，只是方向反过来。

### 17.15 滑动跳动修复 + 试用计费 + 保存方式重构（v1.1.7）

**滑动跳动/残影（真正的根因）**

上一版「单一连续 position」其实没修干净：`offset(for:)` 按 `i == index` 分支取值，而 `index` 又在 `onChange(of: position)` 里随拖动每帧更新。分支在中途切换时，同一张卡的位移公式瞬间改变——卡 1 从 `-4.5pt` 跳到 `+0.5×高度`，这就是跳动与残影。修法：

- 位移是 `d = i − position` 的**单一连续函数**：`d ≥ 0` 走堆叠（`stackGap × d`，向下露边），`d < 0` 走翻页（`d × 卡高`，1:1 跟手飞出）。不再按 index 分支。
- `index` 只在 `withAnimation completion` 里提交：窗口范围、zIndex、页码计数在拖动和动画全程不变。
- 堆叠从「上方露边」改成「下方露边」（offset 正值）。

**试用期扣费为 0**

`monthlySpend` / `remainingThisYear` / `pendingThisYear` 原来直接 `cycle.dates(in:)`，试用中的订阅也算钱。新增 `Subscription.billableDates(in:)`：试用中的订阅只返回试用结束之后的扣款日，试用期内为 0。三处统计统一走它。两条回归测试（试用期内本月为 0、试用结束后正常计费）。

**保存方式重构（彻底摆脱选文件夹）**

用户反复在真机上遇到「文件夹选不了/打开没反应」。不再让用户选目录：

- 主存储固定在 App 内部 `Documents/WSubscription.vault`（`UIFileSharingEnabled` 让它在「文件 > 我的 iPhone > W Sub」可见）。
- 引导页第二步改为「数据保存」说明 + 「打开之前的库」按钮（`fileImporter` 选 `.vault` 备份）。
- 设置「数据」区：导出加密备份（ShareLink 分享 .vault）、导入备份（确认替换后 fileImporter）、立即保存、重新生成恢复码、导出 CSV（明文）。
- 启动时若发现旧版的外部文件夹库（bookmark 时代），自动迁移进 App 内部，之后不再依赖 security-scoped bookmark。

**其他**：卡片底部改为半透明淡紫横条（分类 · 提醒 · 周期）；分类查表从服务模板表改回分类表（原来一直显示「未分类」）；试用订阅「上次扣款」显示「—」。

### 17.16 堆叠视觉修正（v1.1.8）

- **下滑时上一张在当前卡下面**：上一版把 zIndex 固定成「当前卡永远最上」，往回翻时上一张被当前卡挡住，从下面滑出来。改成 `returning = position < index`：往回翻时上一张 zIndex 110 升到最上，上滑时当前卡保持最上飞出。
- **堆叠露边没了**：后面的卡用等比 `scaleEffect(anchor: .top)`，缩小让底部上移约 16pt，抵消了 11pt 的向下偏移。改成**只横向收窄**（`scaleEffect(x:y:1)`），高度不变，向下偏移才能露出底边。
- **露出太多**：stackGap 11 → 7，两条边分别露 7pt / 14pt。
- **逐个递减透明度**：后面的卡去掉压黑遮罩，改整卡 opacity（第一张 0.55、第二张 0.25 保底），淡入页面背景。
- 卡片圆角 26 → 32，淡紫横条圆角 11 → 13，边缘不再锐利。

### 17.17 黑边修复 + 掉帧优化（v1.1.9）

**左上右上黑边**

根因：堆叠的淡入效果用了整卡 `.opacity()`，半透明叠加在圆角边缘与后面的深色卡交错，顶部圆角处露出深色背景缝（尤其 headerBand 只在中间、两角是深色卡体）。修法：

- 顶部横条用 `UnevenRoundedRectangle` 顶部两角 32 圆角，铺满卡片上沿，圆角内不留深色缝。
- 去掉整卡 `.opacity` 离屏合成。

**掉帧**

上一版给 `SubscriptionDeckCard` 传了连续值 `depth`，虽然 `Equatable` 不比较它，但 body 里的派生计算（upcoming/progress/subscribedText）仍随每帧重建被触发。修法：

- 卡片彻底静态化：只持有 `subscription + isDark`，不持有任何随 position 变化的字段。
- 「后面的卡变淡」改回 deck 层的纯色 `.black.opacity()` overlay，SwiftUI 把它合并成单次绘制，不触发卡片 body 重算。
- 卡片 transform（scaleX/offset/zIndex）全部是 GPU 合成，不重排布局。

这已是 SwiftUI 下能做的极限：拖动时每帧只做 4 张卡的 transform 合成 + 一层纯色 overlay，无布局、无 body 重算。

### 17.20 滑动帧率优化到 120Hz（v1.3.0）

SwiftUI 的 `@State position` 每帧更新会触发整个 `SubscriptionDeck.body` 重新求值，这是 SwiftUI 手势驱动的固有限制，ProMotion 屏只能到 60Hz 左右。改用 `UIViewRepresentable` 把「拖动/翻页」这个高频操作交给 UIKit：

- 卡片本身仍是 SwiftUI（`UIHostingController` 承载 `SubscriptionDeckCard`，内容不变）。
- 拖动用 `UIPanGestureRecognizer`，每帧直接写 `container.layer.transform`（translationY + scaleX）和 `layer.opacity`，全部 Core Animation 合成，不经过 SwiftUI diff。
- 松手用 `UIView.animate(usingSpringWithDamping:)` 做弹簧回弹，index 在 completion 里提交。
- 层级改用 `bringSubviewToFront`（比 `layer.zPosition` 更可靠），堆叠露边、下滑返回层级、压黑层、圆角裁剪都在 UIKit 层补回。

### 17.22 回滚 UIKit 卡片叠，修复滑动 bug（v1.4.1）

v1.3.0 为追求 120Hz 把卡片叠改成了 `UIViewRepresentable` + `UIPanGestureRecognizer`，但引入严重 bug：窗口基于整数 `index` 而 `position` 是连续值，拖动跨过整数时卡片 transform 错乱，出现「不显示新卡片、透明卡重叠、闪烁」。

根因：UIKit 版里 `visibleIndices` 固定取 `index-1...index+2`，但 `position` 拖动中已超过 1，导致 `d = itemIndex - position` 把本应「堆叠」的卡算成「翻走」（d<0），多张卡同时往上飞并透明重叠。

修复：回滚到 v1.2.0 的 SwiftUI 版 `SubscriptionDeck`（逻辑正确、反复验证无滑动 bug），并补上 ZStack 显式高度（避免露边被 clipped 裁掉）。放弃 UIKit 直驱方案——正确性优先于帧率，120Hz 优化在保证不引入 bug 的前提下再单独做。

损失：帧率回落到 SwiftUI 手势驱动的水平（约 60Hz）。滑动正确性、堆叠露边、淡紫横条、圆角全部恢复。
